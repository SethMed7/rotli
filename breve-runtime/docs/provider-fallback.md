# Brief generation — the cross-provider fallback chain

*How a brief still goes out when Claude is down. Implemented in `scripts/morning-brief.sh`
(and the lunch/night variants).*

## Why

Brief generation runs headless (`claude -p`). The most common failure isn't the machine — it's
**auth**: an expired Claude login returns `401 Invalid authentication credentials` and every run
dies at model selection. A single-provider pipeline means no brief that day. So Breve chains
**three providers with independent auth** (Anthropic · Google · OpenAI) — a Claude outage/401
doesn't touch the others, and we get a brief unless all three are down (rare).

## The chain

Each step is tried in order; we stop at the first one that actually writes today's brief
(`briefs/<today>.md` exists):

```
1. claude  · $BREVE_MODEL   (settings.json "briefModel" — e.g. sonnet)
2. claude  · $FALLBACK      (haiku; or sonnet if briefModel is already haiku)
3. gemini  · agy            (Antigravity CLI — Google auth)
4. codex   · codex exec     (OpenAI auth)
```

- **claude** invokes the `/breve` skill (`$PROMPT`); **gemini/codex** read the same
  `~/.claude/skills/breve/SKILL.md` directly (`$PROMPT_AGENT`) — same steps, same markdown output,
  so any provider yields the same brief.
- The model is **config-driven** (`scripts/brief-model.ts` reads `settings.json` → `briefModel`).
  Never inherit the floating system default — it was `fable`, then `opus`; a vanished default = no brief.

## Sandbox nuance (per provider)

All providers are confined to your memex + your storage + Breve's own folder (the configured roots), but **how** differs:

- **claude + agy** have no native OS sandbox → wrapped in `sandbox-exec -f $SB` (the
  `breve-write-sandbox.sb` profile, generated by `scripts/sandbox.ts`).
- **codex** ships its **own** Seatbelt sandbox (`-s workspace-write` + `--add-dir`), and nesting it
  inside `sandbox-exec` fails ("can't initialize app-server") — so codex runs **unwrapped** and
  self-confines. Same write boundary, enforced by codex instead of our profile. It also runs with a
  **clean `CODEX_HOME`** (`~/.cache/breve/codex-home`: real auth symlinked, but `config.toml` with any
  `[mcp_servers*]` table stripped) — the brief needs no MCP, and the configured servers only added
  oauth errors + latency. **gemini (agy)** gets a `--print-timeout 15m` (a full brief can exceed 8m).
- Downstream steps (render HTML/PDF, audio, Signal/email send) need **no** model auth.

## What you see when it falls back

- Worked on the configured model → silent (no noise).
- Fell back to another provider → a notification: *"Today's brief was generated with `<provider>` —
  your usual model (`<briefModel>`) was unavailable."* (so a silent outage is still visible). The
  warning has a per-day delivery claim and receipt, so retries or overlapping callers cannot repeat it.
- All three exhausted → a warning to reply "brief" to retry (very rare — network or all three down).

## Worked example (2026-06-21)

Claude returned `401` on **both** `sonnet` and the `haiku` fallback; the chain fell through to
**gemini (agy)**, which generated and delivered the brief. The 401 was a transient token-refresh
blip (Claude worked the prior five days and the credential self-recovered) — not a re-login. This is
exactly the case the chain exists for: a Claude auth failure never costs you a brief.

## Diagnosing a missing/odd brief

- Read that day's `logs/<YYYY-MM-DD>.log` — each `=== try <provider> … ===` / `=== <provider> exit N ===`
  line shows what ran. A `401` on the claude steps = the Claude login expired (`/login` to fix it for
  the *interactive* tier; the headless credential usually auto-refreshes).
- `bash scripts/morning-brief.sh --test` exercises each provider's auth + file access without writing a brief.
